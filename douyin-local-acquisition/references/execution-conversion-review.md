# 执行、咨询承接与复盘

## 一、0粉账号准备

第一个发布日前完成：核对账号状态、完善真实主页、测试实际可用入口、指定接待人、准备首批素材。账号是否存在处罚或限制，应依据后台提示核查，不用“播放低”推断限流。

了解同行和本地需求可以正常搜索和观察；不安排刷固定时长、点赞特定数量、互赞互关或买账号作为起号前提，不将这些行为称为“提高权重”。不要求固定养号天数后才能发内容。

把首批素材集中拍好：一个服务现场、一个工具/流程、一个问题演示、一个门店或服务范围说明。真实不足就缩减数量和频率，不填充假故事。

## 二、30天执行安排

默认每周4—7条，按用户可支配时间选择；不要把每天发一条说成算法要求。发布时段是初始实验变量，可先选接待人在岗、目标客户方便查看的时段；后续结合后台和实际咨询调整，不给全行业“黄金时间”。

| 时间 | 必做事项 | 可核查产出 | 观察与调整 |
|---|---|---|---|
| 第1—3天 | 主页/入口、首批需求或专业视频，逐步补置顶素材 | 主页检查通过、拍摄素材、真实发布记录 | 画面/声音能否看清听清，入口是否可用 |
| 第4—7天 | 交叉发布四类内容，完成首批接待演练 | 已发内容编号、实际咨询记录 | 问题是否与服务相符，回复是否及时 |
| 第8—14天 | 根据首周数据改选题/开头/证据之一 | 第一轮对照内容、补齐必要置顶 | 看同条件内容的变化，不拿单条判断账号生死 |
| 第15—21天 | 展开高相关问题，补充报价和预约解释 | 新稿、实际接待与预约状态 | 哪一步流失，是否超出区域或交付能力 |
| 第22—30天 | 保留有效形式，完成月度复盘 | 内容/线索/成交台账、下月实验 | 哪些问题带来有效咨询，下一轮优先改什么 |

生成用户的30天方案时，把上表展开为发布日排期，至少含：日期/相对天数、视频编号、内容类别、所需素材、行动入口、负责人或角色、是否已成稿。不要只复制这张周计划充当成品。

第一个月优先验证：能否持续生产、客户是否看懂、入口是否可用、咨询是否相关、服务能否承接。不承诺粉丝数、固定播放量、爆款数量、咨询量或成交额。用户要求量化业务目标时用已有数据建立估算，并清楚标假设及区间。

## 三、手机拍摄与发布

默认竖屏、清晰稳定、收音优先，按实际设备拍摄，不要求购买设备。拍前清点道具并检查客户资料；拍后试读字幕，核对专业词和价格条件。

发布包至少包括：封面字、视频稿、字幕重点、发布文案、少量相关话题和实际可用行动入口。真实地点信息可帮助用户理解服务范围，但不是保证本地曝光的开关。

执行状态逐项记录：待拍、已拍、已剪、待核实、已发布。发布成功要有链接、视频编号或后台可见记录；只有生成脚本时不能填写“已发布”。

不因一条播放低就删稿重传或重新注册；先核查后台状态、内容是否清楚、数据是否足够及服务关联。需要处理真实违规时按当前官方提示和申诉路径操作。

## 四、从评论到咨询与预约

公开评论先回答有用部分，再引导用户自愿通过实际可用入口补充情况。不在评论区索要电话、精确门牌、身份证或账单，不群发招揽，不用谐音/拆字规避限制。

接待顺序：**确认区域和问题 → 说明可帮助的范围 → 收集报价必要信息 → 解释费用与限制 → 用户愿意时预约 → 确认履约与实际结果**。

以下为结构模板。生成给商家的最终话术时，要换成真实业务表达，去掉无需收集的字段：

| 场景 | 可改写话术 | 接下来做什么 |
|---|---|---|
| 首次咨询 | “你好，先说一下大致在哪个区，以及想解决什么问题，我看看是不是我们的服务范围。” | 一次问1—2项，别甩长表 |
| 想知道价格 | “我先确认一下具体情况，费用主要和……有关。确认服务内容和是否有额外费用后，再给你报价。” | 补充本行业真实报价因素 |
| 信息不足 | “现在还不能只凭这一点判断。你方便说下……吗？不用发个人证件和精确地址。” | 最少必要信息 |
| 准备预约 | “这个需求在我们的服务范围里。可以先核实可约时间，服务内容和费用确认后再安排。” | 时段真实，必要联系方式私下经同意收集 |
| 暂时不决定 | “没关系，你先按刚才的方法看看。还有变化可以在这里继续说。” | 用户未同意不反复追问 |
| 不在服务范围 | “目前这片区域/这类问题我们暂时接不了，避免耽误你。” | 不为拿线索承诺做不到的服务 |
| 服务完成 | “这次的问题处理得怎么样？还有需要说明的地方可以在这里告诉我们。” | 记录实际反馈；公开案例另征同意 |

接待时间由商家确认。可以设内部目标“营业时段尽量30分钟内初次回复”，但只能是经商家接受的运营目标，不是平台标准或必达承诺。非营业时段说明何时会回复；自动回复和预约组件只有实际开通后才能写“已配置”。

跟进仅针对用户同意或正在进行的咨询；无回应时不要不断催促。后续联系使用其同意的渠道，用户明确拒绝后停止。

## 五、记录口径

内容台账模板见[content-tracker.csv](../assets/content-tracker.csv)，客户线索模板见[lead-tracker.csv](../assets/lead-tracker.csv)。均为空表，不预填客户和成绩。

内容台账至少记录：编号、发布日期/状态、类别、主题、时长、入口、相同观察时点下的后台可得数据、主要评论问题、下一步。

线索台账用匿名客户编号，记录来源内容（不清楚就写未知）、区域到区/街道级、需求、首次咨询时间、接待人、当前状态、下一步、是否同意跟进。报价、预约、到店/上门、成交分别记真实时间，不把预约记成成交。电话和精确地址不要写进默认共享台账。

“有效咨询”的内部定义：服务范围匹配＋有具体需求＋愿意继续沟通；须告知商家并保持一致。它是本Skill的复盘口径，不是抖音官方指标。泛泛点赞、只问“在吗”、重复聊天不新增有效咨询人数。一次咨询产生多个聊天消息仍算一个客户；跨视频来源不明则不硬归因。

| 指标 | 内部计算口径 | 限制 |
|---|---|---|
| 主页访问率 | 主页访问次数÷视频播放次数 | 后台须有匹配范围和观察窗口，不同指标口径不能硬拼 |
| 千次播放有效咨询数 | 有效咨询去重人数÷播放次数×1000 | 是业务参考值，不是算法阈值；只统计可归因部分 |
| 预约率 | 有效咨询中已预约去重人数÷该批有效咨询人数 | 同一批次并说明观察截止时间 |
| 履约率 | 已到店/上门人数÷已预约人数 | 到店与上门不要双算同一客户 |
| 成交率 | 该批有效咨询中实际付费成交人数÷该批有效咨询人数 | 明确成交定义；退款另记 |

分母为0或没有匹配数据时记“无法计算”，不填0%。不同长度视频的完播率不直接等同比较；同城占比、停留/完播、搜索来源等数据只在后台实际提供时记录。后台名称与口径优先于模板。

可先在发布后约24小时和7天观察同一条内容，作为内部记录时点；短周期样本少时只当线索。咨询或成交滞后出现时更新原批次，保持截止时间可见。

## 六、复盘和下一轮实验

第7/14/30天各复盘一次；用户要求即时诊断时使用当前实际资料。没有数据先索取最近5—10条视频可得指标、稿件/链接、观察日期、咨询样本，给出候选原因和低成本验证，不直接定性。

| 观察到的现象 | 先核实 | 下一轮可以测试的一个变量 |
|---|---|---|
| 播放与停留都弱 | 视频能否正常播放、开头是否说清具体问题、声音画面 | 同一问题换更明确的开头 |
| 播放较高、咨询不相关 | 客户区域、业务关联、是否靠泛娱乐吸引人 | 改为更具体的本地需求场景 |
| 有主页访问、少咨询 | 入口是否可用、服务范围与报价方式是否清楚 | 简化入口或补一条服务流程稿 |
| 有咨询、有效需求少 | 区域、服务和优惠是否引来不匹配的人 | 明确适用条件与服务边界 |
| 有效咨询多、少预约 | 回复时效、费用疑问、实际排班与交付能力 | 改一项报价说明或预约步骤 |
| 预约后不履约 | 时间地点是否清楚、提醒是否获同意、临时变动 | 简化预约确认与必要提醒 |

以上是候选解释，不是因果结论。每轮选择一个主要改动，尽量在类似主题、时长、观察窗口下比较3—5条；样本不足就继续观察，不能把内部样本建议写成平台标准。

下轮输出：保留什么、暂停什么、改哪个变量、用哪些视频验证、观察到何时、负责人是谁。形成能执行的动作，不只说“优化内容、提高转化”。
