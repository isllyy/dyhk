# 抖音同城获客与0粉起号

把商家的真实服务变成可发布、可承接、可复盘的内容。优先帮助服务范围内、有实际需求的人完成咨询和预约；播放量和粉丝量是辅助观察指标。

默认适用于通信门店、宽带安装、手机维修、家政、餐饮、汽修、美业等本地业务。涉及特殊行业时先核验当前资质、宣传和交易要求，不把普通门店话术直接套入医疗、金融、教育等业务。


## 运营红线：每次生成前必读

**先读取[运营红线与发布审核](references/operating-redlines.md)，再执行任何模式。**本版本（v1.1.0，2026-10-20）默认执行用户提供的短视频、直播、微信运营红线；它优先于旧选题、案例、通用营销建议和输出模板。内部分析可以记录禁词，公开输出不得照搬。

按“违禁词清单＋画面红线＋审核把关”执行；直播只围绕终端手机使用与真实服务，不展开受禁业务。内容生成包含文字初查、语义复核、画面/声音检查和真实人工审核状态。不得把未审稿标成可直接发布。

可用[文字初查程序](scripts/check_redlines.py)扫描独立公开稿；[词表](assets/redline-terms.json)仅为检出依据，不覆盖全部语义。生成时可参考[公开稿示例](assets/public-copy-example.md)。没有素材时只报告文字检查，画面与声音记待审。

## 1. 选择本次工作模式

根据用户请求选择，保持已有商家信息和确认过的事实：

| 用户意图 | 交付范围 |
|---|---|
| 起号、完整方案、从零开始 | 执行完整起号流程，交付第7节的全案 |
| 今天拍什么、选题、口播稿 | 只生成所需选题或完整拍摄包，读取[内容生产规范](references/content-production.md) |
| 播放低、没咨询、复盘 | 读取[执行与获客复盘](references/execution-conversion-review.md)，先看实际数据，再给下一轮实验 |
| 多个门店或员工一起做 | 每个账号独立定位和真实素材，在用户要求的数量内制作；不把同一稿件批量换城市名 |

不因调用本Skill自动发布、私信客户、投广告、购买认证或开通付费服务。用户已授权的具体操作可按实际工具能力执行，并核实结果；文案生成不能报告为已发布。

## 2. 收集最小可用信息

先读本轮输入、上下文和用户指定资料。能确定的信息不重复问。

完整起号至少需要：**行业/服务、城市或区域、主推业务、目标客户或典型使用场景**。目标客户不清时，可根据服务提出一个明确假设，让用户修正。主推业务不清时提出2—3个候选，让用户选择，不同时推所有业务。

缺少关键项时，只问一轮、最多3个合并问题；把已知信息预填进去。不要用长问卷拦住用户。只有涉及定位和服务本身的缺失才等待回答；可先整理资料和框架。

可选信息：称呼/团队、服务范围、地址、营业时段、真实从业经历、可证明的优势、价格与限制、账号现状、出镜意愿、每周拍摄时间、咨询接待人、可用经营入口、现有素材。

用户只给一句话时可用这段收集信息：

> 请补充：①做什么业务、在哪个城市/区；②这次最想推什么服务、主要服务哪类人；③能否出镜、每周大约能拍几次。有店址、价格或账号截图也可以一起给。

确认并展示一个简短的“商家事实卡”：

| 字段 | 已确认事实/执行假设/待确认 |
|---|---|
| 城市与核心服务区域 | 不擅自扩大到全城 |
| 核心客户及需求场景 | 本期优先一个主场景 |
| 主推服务与交付边界 | 能做什么、暂时不能承诺什么 |
| 人物/门店与可信证据 | 年限、授权、案例均需有依据 |
| 拍摄资源与发布频率 | 根据时间和素材确定 |
| 咨询入口与接待人 | 明确谁来接、何时能回复 |

对未确认的价格、地址、活动、资质、年限不编造。策略中可标“待确认”；**可发布稿不能夹带未填事实占位符**，应改写成不依赖该事实的版本。无法改写时将整条标为“备选，确认后再发”。

## 3. 先设计服务和获客路径

先写清：客户遇到什么问题 → 视频给出什么帮助 → 看见什么可信证据 → 通过哪个入口咨询 → 谁接待 → 怎样预约/到店/上门 → 怎样记录结果。

为主推业务整理一张服务卡：适用人群、交付内容、费用构成或报价方式、不包含事项、服务区域、预约方式、真实证据。不把未经确认的“免费检测、随时上门、全城可办、最低价”写成承诺。

只选一个主要行动入口，按账号当前可用能力决定：站内私信、实际开通的预约/线索组件、符合业务条件的门店或团购入口等。功能未知时，先提供站内咨询方案并标注待核实，不虚构开通条件、菜单路径和审核时长。

对标不是必需前置。若用户提供账号或可浏览公开资料，可对比3—5个同地区/同业务账号：主页承诺、内容类型、真实服务证据、咨询入口与可复制的拍摄方法。记录链接、观察日期和可见范围；不可把不可见的成交量写成事实。无法访问时说明未完成实时对标，用搜索词和观察表代替虚构对标。

## 4. 建立能承接咨询的主页

交付以下内容，均围绕商家事实卡：

- 一句话定位：服务区域＋服务人群＋解决的问题＋可信理由；理由不足时用透明服务过程，别造资历。
- 人设：称呼、职业身份、说话方式、可展示的服务习惯。真人、服务团队或门店视角均可，不强制“姐姐型”或职业装。
- 昵称3组选项及推荐理由，简洁、可读、与真实业务一致；不声称使用某关键词就能获得排名。
- 简介4行成稿：服务区域/身份、核心服务、可信的服务边界、一个咨询入口；没有固定门店的账号写服务区域，不编地址。
- 头像与背景图的可执行拍摄/设计说明：清晰可辨、真实身份或业务识别、手机上可读；不擅用授权标识。
- 主页检查表：名称/简介/视频承诺一致，入口能打开，接待有人负责，已公开信息准确。

三条置顶内容分别讲“我服务谁”“一个真实问题怎么判断”“怎样找我及服务流程”。不强制把置顶素材占满首三天；可先发最容易拍好的需求视频，再补齐置顶。没有置顶功能时用系列封面和简介组织。

## 5. 设计0粉内容组合

保留四类内容，但不把它们写成平台的四个算法阶段：

1. **本地需求与共鸣**：具体服务区的人在什么场景遇到什么问题，话题须能接回业务。
2. **专业解答与选择**：判断、比较、避坑、自查；提供有用步骤和适用条件。
3. **信任与服务证据**：真实工作过程、工具、报价解释、服务边界、经授权的案例。
4. **服务与行动**：什么情况适合找你、怎么预约、如何报价；没有优惠也能写。

40条选题默认四类各10条，作为可选内容库，**不等于发布比例**。每条都有标题、目标客户/需求、类别、核心回答、证据或素材、拍摄方式、一个行动引导。具体写法见[内容生产规范](references/content-production.md)。

起步建议：每周4条时先尝试需求1＋专业1＋证据1＋服务1；每周7条时可尝试需求2＋专业2＋证据2＋服务1。它们只是初始实验安排，按资源和结果调整。首周就保留自然的咨询机会，不等积累粉丝后才承接。

城市名可自然出现在口播、场景、字幕、标题或地点信息中；不强制每条标题塞城市名，也不堆一串地点词。搜索表达使用客户会问的问题＋真实区域＋具体业务，是否被搜索或推荐要看后台，不能保证。

## 6. 写成能直接拍摄和执行的方案

全案、选题和稿件读取[内容生产规范](references/content-production.md)；排期、发布、接待与复盘读取[执行与获客复盘](references/execution-conversion-review.md)。需要核对平台规定或功能时读取[官方资料与核验边界](references/sources.md)，并尽量实时查官方来源。

普通方案默认自然流量、手机拍摄、已有门店/工具，不要求投流、专业设备、认证或直播。用户明确提出这些需求时再增加相应部分，并核对当前资格和费用。

不方便出镜：手部操作＋现场画面＋本人配音，或门店走拍＋字幕解说。不拍得到客户案例：用自己的设备演示、服务流程或常见问题，不演成刚发生的客户故事。

兼职运营：把频率降至能持续完成的水平，一次集中拍摄，多条使用不同问题与实质内容。素材多也不安排超出接待能力的优惠或承诺。

## 7. 完整起号方案的默认交付

按以下顺序交付，可保存为Markdown或用户指定格式：

1. 商家事实卡、执行假设和最少待确认项。
2. 一句话定位、人设、主推服务卡、获客路径及阶段目标。
3. 账号主页成稿：昵称、简介、头像/背景图方案、入口检查。
4. 三条置顶视频完整拍摄包。
5. 40条不重复的选题库，标明首周优先项与素材可得性。
6. 首周执行排期，默认7条完整拍摄包；兼职版按实际频率调整。置顶稿如复用，明确对应编号，不把同一条算两条。
7. 30天按周推进、按发布日执行的安排，每个发布日写内容编号、准备素材、行动引导、负责人/角色；有休息或集中拍摄日也明确写出。
8. 评论/私信接待话术、预约步骤、服务边界和线索记录表。
9. 第7/14/30天复盘表与下一轮实验规则。
10. 今天先做的3—5件事，以及哪些稿可立即使用、哪些素材需补齐。

第8天后的具体台词由选题库按需展开，首次交付写清“已交完整稿的编号”和“只有选题、尚未成稿的编号”。用户要求30条或40条完整口播稿时按要求扩展，不能以选题提纲替代。输出太长时先保存完整文件再展示摘要；工具无法保存时连续分批交付并标总数，不说已完成但只交几条示例。

## 8. 发布前自检与结果表述

- 选题是否能对应服务区、目标人群、真实问题与可提供的服务？
- 全文是否擅自编造客户、成交、证书、年限、价格、统计数字或算法结论？
- 口播是否有完整可念正文、画面、封面、发布文案和一个行动入口？
- 是否能按手头素材拍完？没有素材是否给出真实替代拍法？
- 公开内容是否暴露住址、电话、账单、工单等个人信息？经授权展示并遮挡无关信息。
- 是否存在诱导互动、骚扰私信、互刷买量、照搬同行、虚假身份或夸大效果？有则删除或改写。
- 是否把“建议”“假设”“公开来源事实”区分清楚？不能以固定播放门槛解释所有账号。
- 结果只报告到可见状态：已生成、已保存、待核实、已发布、已收到咨询、已预约、已成交分别记载。

事实核实和文字检查完成后可标“可拍摄草稿（发布审核未完成）”；发布状态另按红线审核记录确定。未发生的发布和咨询不得生成到台账里。
